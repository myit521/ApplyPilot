# T4 逐项证据匹配执行记录

开始与验收：2026-10-03。基线：`c116311`；分支：`codex/evidence-matching`。按已确认设计扩展既有 `/api/jobs/{id}/match` 与 `/jobs` 职位详情。

## 实现内容

- 匹配前要求职位已有成功解析；不存在职位返回 404，未解析返回 409。
- 报告列出必备条件、加分项和职责，以及未归入这些条目的独立技术关键词。若解析器没给某个文本项提取可核对关键词，该项标 unknown 并说明原因；解析 unknowns 也单列。
- 只以启用且已确认事实的技能标签和正文做关键词核对。技术名使用 ASCII 字母/数字边界，避免把 Java 误当作 JavaScript。所有关键词都有命中标 supported，部分命中标 partial，完全没命中标 no_evidence。
- 每个命中事实带 ID、修订、来源名、事实类型、围绕正文命中关键词截取的最多 500 字内容片段、命中的技能标签、关键词和命中依据。报告随请求实时计算，不落新表。
- `include_semantic` 默认 false。显式 true 时额外列出仅语义召回且没有上述关键词证据的候选；候选不会提升报告状态。职位页用文字节点显示状态、说明、事实引用、未知项和候选提醒。
- 不调用 LLM 作匹配裁判，不计算录用概率；没有新增依赖或迁移。数据真实性、上下文含义和语义同义词仍须人工判断；后续事实规则校验见 T5，冻结报告历史见 T7。

## 当前限制

这是确定性的词面基线。解析器关键词抽取错误会影响映射；无关键词条目显示 unknown，不猜测语义。词面命中仍须人读摘录确认语境。旧 `candidates` 混合检索字段为了兼容仍可能含 ILIKE 子串噪声；新报告的状态和证据按独立精确关键词规则计算。向量召回需要首次模型缓存并可能耗时；页面默认关闭。未真实调用 LLM，无性能或质量百分比声明。
