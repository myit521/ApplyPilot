## 1. 当前测试复现（T5 验收：2026-10-03）

Windows Python 3.13.5，按 README 在隔离虚拟环境安装 requirements.lock。锁文件来自固定直接依赖的独立解析，不是全局环境 freeze；T1 安装后 89 个依赖兼容；T2 最终全套测试 72 passed。T3 最终全套测试 108 passed。T4 最终全套测试结果见 [T4 执行记录](t4-execution.md)，T5 结果见 [T5 执行记录](t5-execution.md)。

### 无 Docker 的单元/运行测试

T3 最终无 Docker 测试 75 passed、33 deselected。T4、T5 最终无 Docker 测试结果分别见 [T4 执行记录](t4-execution.md)、[T5 执行记录](t5-execution.md)。

包含原有纯逻辑测试及新进程导入、生命周期、不可用数据库、连接释放和就绪回归。不会启动 Docker 或加载嵌入模型；API 模块在收集阶段不再连接数据库。T5 无 Docker 结果为 99 passed、36 deselected；语义复核解析失败改为阻断，具体失败路径见执行记录。

### 完整测试

启动 Docker Desktop，然后执行：

```powershell
python -m pytest -p no:cacheprovider -q
```

不需要额外的导入数据库，也不需要设置 DATABASE_URL；集成测试使用自己的临时 PostgreSQL 容器。API 测试仍可能下载嵌入模型。本次使用已有缓存，并设置 HF_HUB_OFFLINE=1、TRANSFORMERS_OFFLINE=1；只有缓存完整时才能用这两个选项。生成模型使用替身，不需要真实密钥。

requirements.lock 当前只验证 Windows/Python 3.13；其他平台应另行解析和验证，不宣称跨平台锁。使用 uv 创建不含 pip 的虚拟环境时，可用 `uv pip check --python .venv/Scripts/python.exe` 检查兼容性；标准 `python -m venv` 环境可使用 pip check。

### 健康与故障处理

- `/health/live`：进程存活返回 200，不访问数据库。
- `/health/ready`：应用 checkpoint 可用，当前数据库可连且必要业务表存在时返回 200；否则 503，响应不包含连接串。
- 启动时 checkpoint 初始化失败：保留诊断接口，业务请求 503；修复数据库后重启。
- 运行中原 checkpoint 长连接失效：即使新连接可用也返回未就绪；本阶段不自动重连。
- 检查不覆盖模型密钥、嵌入缓存、列级 schema 兼容或任务恢复。这些限制必须与“就绪”一起解释。

2026-09-29 的 38/48 项旧结果保留在审计基线，不改写。T3 页面另以 Microsoft Edge 无头浏览器和临时 PostgreSQL 验收保存、原文留存、显式解析、解析失败提示、历史分页、输入错误时保留表单内容及 HTML 惰性显示；该 UI 冒烟使用合成模型，不覆盖真实模型质量。T4 另用 Microsoft Edge 无头浏览器验证匹配报告的部分支持/无证据/支持、事实引用、未知项及草稿/停用/JavaScript 误匹配排除；页面无 JavaScript 错误。smoke 脚本会调用真实模型，运行前检查样例数据和预算，不作为默认无成本测试。

## 3. 评测设计

P0 至少准备 10 份脱敏/合成 JD 和 20 条边界主张。JD 标注要求及可支持事实，主张标注支持、越界、无证据或不确定，并记录判断理由。P1 扩展到至少 30 JD，覆盖不同岗位方向。

每次记录：数据版本、代码提交、模型标识、提示版本、参数、输入/输出摘要、耗时、token/费用（提供方可用时）、错误与人工标签。真实模型可能不确定，保存失败样例，不只保留成功输出。

| 指标 | 计算和限制 |
| --- | --- |
| 主张支持率 | 有证据支持的生成主张 / 所有已生成主张；失败运行单独报告，不能悄悄排除 |
| 违规拦截召回率 | 被拦截的标注违规主张 / 全部标注违规主张 |
| 拦截精确率 | 确为违规的被拦截主张 / 全部被拦截主张 |
| 要求证据覆盖 | 找到有效证据的要求 / 人工标注为可支持的要求；同时报告无证据要求数量 |
| 检索 Recall@5 | top-5 命中的标注相关事实 / 全部标注相关事实；无相关事实样例单列 |
| 流程完成情况 | 成功、失败、待人工、取消的运行数量及原因 |
| 人工修改成本 | 同任务的修改条数或计时，说明样本和计时方式 |

分母为零时报告 N/A 和样本数，不能自动填 100%。批准后的支持率可单列，但不能替代所有生成结果的支持率，否则会掩盖被拒绝内容。不要把匹配分数叫“录用概率”。

比较关键词和混合检索时使用相同资料/JD；只有可复现增益才保留额外复杂度。当前没有以上指标的正式基线，禁止引用占位百分比。

## 4. 演示脚本与完成定义

准备合成身份、两段确认经历、一份缺乏证据的经历和两份 JD。演示页面清楚标识替身模式或真实模型模式。

1. **正常流程**：确认资料 → 录入 JD → 展示逐项证据 → 编辑草稿 → 重验批准 → 导出并打开 DOCX → 手工登记投递 → 查看绑定版本。
2. **可信边界**：把“参与评审”改为“独立实现”或添加无来源数字；应阻断批准，展示原因。复核不可用时显示待处理。
3. **一致性与恢复**：在临时环境令引用写失败，确认无半版本；修复后重试仅一个版本。中断任务并重启，展示恢复或明确人工处理入口。
4. **结果留痕**：仅导出时不能显示已投递；用户报告和网站回执分别标记，未知结果保持未知。
5. **可选插件**：合成资料在受控页面预览、确认、填写和回读；不把 fixture 验证描述为招聘网站已兼容。

P0 完成要求上述前四项可重复运行、相关测试通过、已知问题可见、没有真实隐私数据混入演示。

## 5. 最低观测、安全和恢复

P0 日志至少含 run/task/job/version ID、步骤、耗时、错误类型、重试次数；不含密钥、完整 JD/简历、手机号和邮箱。模型费用与配额需有明确上限或停止机制，不能无限重试。

健康检查表示进程存活；就绪检查表示必需依赖可用。故障手册说明数据库不可用、模型超时、待审核任务、冻结失败、恢复失败如何处理，以及何时不该重试。

备份演练必须恢复至独立实例并核对版本、引用和应用记录；“备份命令成功”不等于可恢复。迁移前保留备份，不以删除数据卷替代升级。

本机单用户不代表可公开部署。开放访问前补认证、对象归属校验、限流、日志和删除策略。未来 URL 抓取与扩展分别增加 SSRF、来源验证、配对鉴权和提示注入测试。
