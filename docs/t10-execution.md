# T10 页面与导出执行记录

验收日期：2026-10-09。基准提交 `45a1959`，分支 `codex/t10-page-flow-and-docx`。本阶段打通项目自身页面中的职位匹配、草稿启动、审批、导出与人工投递记录入口；不自动访问招聘网站或提交简历。

## 实现与边界

- `/jobs` 详情在已解析 JD 上生成实时匹配报告；用户先核对报告，才可从页面启动草稿。创建请求带浏览器生成的幂等键，显示持久任务状态和审核入口；首页也可取消未批准任务。网络错误时保留同键供重试，终态失败或取消后可重新创建。
- 审核页正确处理批准后已冻结但 checkpoint 暂待对账的响应，重新加载冻结版本与恢复入口；联系资料未确认时提示，已批准旧版本缺少资料快照时提示。实际批准仍由用户点击，编辑与退回沿用 T6/T7 门禁。
- 新批准包为 schema 2：批准事务内对已确认联系资料读取修订和五个联系字段，连同职位、主张、事实引用纳入内容哈希和版本 JSON。未确认/不存在的联系资料记录为 `null`，不阻断批准；旧 schema 1 的哈希与读取保持不变。DOCX 只使用版本中的冻结资料，不从当前资料补填旧版。导出 API 拒绝草稿版本。
- DOCX 显示姓名、已有联系方式、应聘岗位及三个内容分区。导出、批准和人工登记是三件不同的操作，记录的 `submitted` 仍只表示用户自述。
