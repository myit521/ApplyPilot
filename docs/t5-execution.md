# T5 校验门禁执行记录

开始与验收：2026-10-03。基线：`4ca1cba`；分支：`codex/t5-validation`。T5 按现有确定性校验和语义复核工作流加固，不新增模型、依赖或数据库迁移。

## 实现内容

- 空白简历主张返回 `EMPTY_CLAIM`；所有分区均为空时返回 `EMPTY_RESUME`。校验错误沿既有重试路径返回生成节点，连续失败后进入 `FAILED`，不能到达审批中断点。
- 数字用完整数值和单位边界核验，`16 个` 不支持 `6 个`，`6` 不会从 `6,000` 中误命中，逗号分隔的 `6, 7` 会分别校验。保留日期标点，已确认教育字段中的完整日期仍可支撑日期数字。
- 技能只在引用事实技能标签中按完整技术词边界核对。`Java` 不支持 `JavaScript`，`SQL` 不支持 `MySQL`；`C`、`C++` 和 `C#` 按独立技能判断；`SQL` 仍可被 `SQL预览` 等完整标签覆盖。
- 语义复核要求根对象严格包含 `violations` 数组，每条越界项必须提供非空 `claim_text` 和 `reason`，并精确对应本轮生成主张。只接受单个完整 JSON 对象（或完整 JSON 代码围栏），拒绝解释文本和重复键；DeepSeek HTTP 请求使用 60 秒超时。超时/调用异常、空响应、无效 JSON、结构错误或未知主张返回 `SEMANTIC_REVIEW_UNAVAILABLE`。
- 语义复核不可用时工作流立即进入 `FAILED`，错误提示待人工处理；不将服务故障当成无越界，也不把基础设施故障作为内容反馈重试。人工审批接口只接受停在审批节点的工作流，因此失败结果不能冻结为批准版本。

## 限制

语义复核仍依赖模型判断，模型返回格式正确也不能证明事实真实或模型判断无误；用户仍须核对内容。复核不可用时当前状态为 `FAILED` 并通过工作流 API 返回错误，不提供人工强制放行按钮。A05 模型伪造事实来源属于 T2 已完成边界，不在 T5 重复实现。
