## 最小修复

只改 `applications_page` 查询：公司/职位名优先读取 `resume_versions.content.job_snapshot`；缺少相应字段的旧版沿用 live jobs 兼容，已保存的空字符串不被填成当前值。明确请求且具有 `workflow_approvals` 记录的 version_id 优先保留在列表，其余按批准时间与版本 ID 倒序，仍限制 100 项；参数化查询，不新增分页、状态或数据库迁移。旧版只有 status=approved、没有审批行的导出兼容，不等于允许创建新投递记录。

列表对应的历史行标签使用该选项文本：快照包含相应字段时显示冻结值，缺字段仍按上一段回退当前职位值；部分快照可以混合冻结字段和兼容回退字段。未包含在当前选择列表中的更早历史行仍可退回显示 job/version 编号，不宣称完整历史分页已实现。DOCX、批准事务、人工来源与外部提交边界不变。
