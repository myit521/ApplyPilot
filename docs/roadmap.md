## 范围与容量

必须演示：确认资料和事实 → 录入 JD → 逐项匹配 → 定制草稿 → 编辑校验 → 人工批准 → 自行投递并留痕。

保留 Python 单体。浏览器扩展不是必交付项；稳定的结构化资料和批准版本契约属于 P0。

假设单人熟悉项目、每天投入约 5–6 小时。P0 **66 小时**，缓冲 **8 小时**，总计 **74 小时**。每天仅 4 小时则两周容量不足，应延长周期或减少样式和模板，不能牺牲事实确认、审批一致性与恢复。

## P2：需求驱动增强

| 方向 | 启动条件和验收 | 测试 / 工时 / 依赖 |
| --- | --- | --- |
| 合规职位采集 | 明确来源及允许方式，失败退回粘贴 | SSRF/超时/页面变更；1–3 天每来源；T3 |
| 更多网站适配 | 有真实需求与允许测试条件，不自动提交 | fixture+人工验证；1–3 天每站起；S3 |
| 更多模板 | 基础模板稳定且有排版需求 | 多长度视觉验收；1–2 天每模板；T10 |
| 多实例和队列 | 实测瓶颈或明确部署要求 | 竞争、租约失效、恢复；另行估算；T8 观测 |
| Java 迁移/拆分 | 业务或团队边界明确，收益高于双栈成本 | 等价行为和迁移验证；单独立项 |

暂不做验证码绕过、自动提交、批量骚扰投递、通用浏览器 Agent、多 Agent 辩论和无评测支撑的复杂 RAG。
