## 开始前的方案审查

T27 实际运行出现应用模型类型未登记的 msgpack 警告。现有锁定依赖为 langgraph-checkpoint 4.2.0、langgraph-checkpoint-postgres 3.1.2，支持每个 serializer 的精确白名单。此次使用既有接口，不升级依赖、不设置全局环境变量、不自行实现解码器。

验收目标是应用已知类型可以读取、未知类型不能任意导入并执行构造器，以及旧格式中断可以在重启后恢复。库的严格模式可能将被阻止的对象降为原始参数或字典，不能将“阻止未知构造器”写成“整条 checkpoint 必然拒绝”。数据库仍须保持可信、限制访问。

## 修改范围与兼容边界

- 默认应用拥有的 PostgreSQL saver 使用显式 serializer，逐一登记 WorkflowState 可达的应用模型与枚举，保留库内置安全类型；不开放整个 applypilot 模块。
- pickle fallback 显式关闭。JSON 路径沿用锁定库原有默认安全策略，不增加应用构造器白名单。
- 注入的测试或调用方 checkpointer 保留原有注入语义，其配置由调用方负责。此次不替换或改写外部传入对象。
- 不迁移已有 checkpoint 字节。测试使用当前锁定版本的旧默认 serializer 生成合成旧格式，验证兼容，不证明任意历史依赖版本或真实用户旧数据均可加载。
- 框架内置安全类型及图编译时的自动类型登记仍是依赖行为；本次不是仅允许这几个类的完整隔离沙箱，也不提供数据真实性或所有字段的安全验证。

升级前按 T12 备份，停止旧应用进程；在备份副本运行兼容测试，再切换。出现未知类型或加载异常时保留备份和错误类型，停止反复重试并人工核对版本/类型来源；不要开启 pickle、通配模块或全局放行来“修复”。不删除数据卷，不向模型发送 checkpoint 内容。

## 委派与验收

CodeBuddy 候选实现任务只获准读取限定源码与依赖 serializer 源码，在指定忽略目录写文件；不执行命令、读密钥、提交或推送。超过约定时间仍无候选、stdout 或 stderr，主审核实进程身份后停止，保留退出记录，不算有效交付；没有因超时重复派发实现。最终 helper、接线和测试由主审完成，另派独立只读审查。

生产接线测试先在旧代码上因缺少显式 serde 失败，再接入新配置。离线反例将工厂临时替换为旧默认 serializer（不改文件）：6 failed、1 passed，随后正式配置下 7 passed，覆盖四种未知构造器编码不导入目标、pickle 不执行、全局严格开关不影响显式策略。pickle 默认原本关闭，本轮明确固定该配置，没有将它描述为新发现的漏洞。

运行时及 PostgreSQL 针对性测试为 10 passed：旧宽松 serializer 写入合成待审批和校验失败状态，关闭连接，新 serializer 读取后逐项核对模型、日期、旧草稿、错误枚举和中断值；继续批准不新增模型调用。
