# 产品与架构设计

更新：2026-10-03。本文描述推荐目标，**不是完成清单**。现状见[审计](audit-2026-09-29.md)，执行见[路线](roadmap.md)。

## 1. 用户问题与产品边界

面向需要针对多个校招职位调整简历的个人求职者，解决经历分散、模型夸大贡献、版本混淆和投递后无法追溯的问题。价值在于「内容有依据、决策有人审、结果可追踪」，不是自动投递数量。

默认先面向国内企业校招，具体网站尚待实际需求确定。MVP 采用粘贴 JD，URL 仅作来源元数据，不自动抓取。系统不能替用户证明经历真实，也不能预测录用概率。

```mermaid
flowchart LR
  A[录入资料与事实] --> B[人工确认]
  B --> C[粘贴职位 JD]
  C --> D[逐项匹配证据]
  D --> E[生成和编辑]
  E --> F[校验并批准版本]
  F --> G[用户自行投递]
  G --> H[记录版本和结果]
```

## 2. 架构决策

保留 Python 模块化单体。Java 求职方向不构成整体重写的理由；不增加只有转发功能的 Java 门面。后续有明确部署、团队或业务约束时再评估迁移。

| 组件 | 必要职责 | 决策 |
| --- | --- | --- |
| FastAPI + Jinja2 | 本机录入、审核、查询、导出 | 保留，补全流程页面 |
| Pydantic | 输入及模型输出结构约束 | 保留；结构正确不代表事实正确 |
| PostgreSQL | 业务记录、版本、任务和事件 | 权威业务存储 |
| LangGraph | AI 节点、有限重试、人工中断 | 保留在生成流程，不接管所有 CRUD |
| 模型适配层 | 提取、受限改写、语义辅助复核 | 明确输入范围、错误和预算 |
| 关键词匹配 | 小型个人事实库的可解释基线 | 先建立评测 |
| pgvector | 语义召回实验 | 当前仍依赖；目标是可关闭，收益验证前不强化 |
| 单实例有界 worker | 持久化任务执行、限制并发、重启恢复 | 替换裸 daemon thread，不先引入 Redis/MQ |
| 浏览器扩展 | 用户触发的扫描、预览、填写与回读 | P1；先验证外部 JSON 桥接 |
| Playwright | UI 回归和受控表单测试 | 测试用途优先，不默认作为投递驱动 |

业务表决定批准和冻结是否成功；checkpoint 记录图运行位置；worker 根据持久化任务安排执行。checkpoint 存在不等于服务会自动恢复。

## 3. 数据模型与可信边界

以下是目标概念，按任务增量建模，不预建全部未来表。

| 概念 | 必要数据 | 不变量 |
| --- | --- | --- |
| ProfileRevision | 联系方式、修订与确认状态；关联教育事实 | 联系资料独立修订；教育唯一来源为 FactRevision |
| FactRevision | 动作、贡献范围、技能、数字、来源 | 模型不能把 self_report 升级为已验证证据 |
| Job | 原始 JD、公司、职位、来源和时间 | 保留原文，解析可纠正 |
| MatchReport | 要求、证据、状态和解释 | 支持/部分支持/无证据/未知分开 |
| DraftRevision | 内容、引用、反馈和校验 | 编辑产生新修订，旧批准失效 |
| ResumeVersion | 批准内容、来源快照、哈希 | 不随事实修改而漂移 |
| Task | 请求摘要、状态、尝试、错误和时间 | 先持久化占位，再执行 |
| Application | 职位、版本、渠道、时间、结果来源 | 导出、填写、提交分别记录 |
| AuditEvent | 操作者、动作、版本和时间 | 不保存密钥或完整敏感内容 |

用户确认仅表示认可记录，不构成第三方真实性证明。证据须用户提供或独立核验，模型生成的 commit 或链接不能直接变成可信来源。

结构化资料与生成文案分开：联系方式、教育不经过 top-K 经历召回。事实内容修改必须使旧向量失效；停用事实阻止后续生成。历史版本保存快照并提示来源状态变化，不静默改写；再次使用受影响内容需重新审核。

### 职位录入契约（T3）

保存职位与模型解析分开。`POST /api/jobs` 保存用户填写的职位、公司、来源、可选 URL 和 JD 原文，不调用模型；`POST /api/jobs/{id}/parse` 才显式解析。解析结果单独存放，不覆盖用户填写的职位名；失败后原记录仍可查询并重试。URL 只作为来源文字保存，不发起抓取。

职位名/公司各最多 200 字符，来源最多 100 字符（默认 paste），均不得为空白；JD 最多 30,000 字符且不得全为空白，保存时保留首尾空白和换行。可选 URL 最多 2,048 字符，仅接受带主机名的 HTTP(S) 地址，不接受凭据或空白/控制字符。历史按 ID 倒序，以 limit/offset 查询（默认每页 20，最多 100），详情展示原文与来源。现存缺少元数据的历史行仍可读取，不自动补造公司或职位。

本阶段不提供职位编辑、删除、自动采集或重复录入幂等保证；重试保存前先查历史。匹配报告由 T4 实施；本页面当前可生成实时的逐项关键词报告，不创建持久报告快照或生成工作流。

### 逐项证据匹配契约（T4）

匹配 API 只接收已解析 JD。对必备项、加分项和职责，解析器明确关联到条目的技术关键词才参与状态判定；关键词逐个在启用且已确认事实的技能标签或内容中精确匹配。全部匹配为 supported，命中一部分为 partial，零命中为 no_evidence；没有可核对关键词为 unknown。解析器列出的 unknowns 独立展示，不能混成“无证据”。每条证据展示事实 ID、修订、来源、类型、围绕正文命中词截取的内容片段、命中的技能标签、命中词和命中依据。

报告是每次请求现场计算，不冻结历史快照。语义召回默认关闭；显式开启时只列出没有关键词证据的待核候选，不改变状态。该基线不做技能语义同义词判断，`supported` 表示列出的词在事实文本/技能标签中找到，不代表经历真实性或岗位胜任承诺；仍需人工核读上下文。旧混合召回可能包含 ILIKE 子串噪声，候选列表不用于状态判定。

## 4. 匹配和生成规则

按 JD 要求逐项列证据。「无证据」不等于候选人没有能力；提取不确定时显示未知并允许补充。不将模型评分包装为录用概率。

只使用已确认事实生成；每条主张绑定事实修订。空简历/空白主张不能进入审批。数字及单位按完整边界核验，技能按引用标签中的完整技术词核验；不能由 SQL 推导 MySQL 实操或由 16 个推导 6 个。

校验顺序：结构和非空 → 引用及修订 → 数字和技能边界 → 贡献范围和语义复核。模型语义复核必须返回单个完整 JSON 对象（可由完整 Markdown 代码围栏包裹），不得附带解释文本、重复 JSON 键或不对应本轮主张的条目；结构无效时失败待人工处理，不自动放行。模型调用设有有限超时。模型复核不能替代规则与人工审核。

拒绝意见必须进入下一次生成请求，但不能覆盖系统事实约束。人工可编辑已有主张文本，引用由服务端保留；编辑产生新的草稿修订并重新校验。审批和编辑均须提交当前修订号，过期请求返回 409。审核页显示上个修订与当前草稿的文本差异；已批准版本不可在原工作流内修改。

## 5. 审批与任务一致性

目标业务状态包括待执行、执行中、等待补充、等待审核、批准完成、失败和取消，不能误认为当前已有枚举。

批准请求绑定 run、draft revision 和内容哈希。一个业务事务写入批准决定、完整版本、主张引用和审计事件，以唯一约束防重复。事务提交后才能显示版本可用。

checkpoint 与业务事务不天然原子。推荐先提交权威批准记录，再由图幂等读取决定继续；图推进失败时依数据库对账恢复。重复批准返回同一完整版本，不能出现 READY 但引用缺失。

创建任务原子占用幂等键并保存请求摘要。相同键同请求返回原任务，不同请求返回冲突。worker 持久化错误和尝试次数，启动时检查中断任务；外部模型调用可能重复产生费用，不承诺 exactly-once。

取消后，即使已发出的模型调用返回，也不得继续推进任务。临时错误有上限退避，输入错误、事实不足和授权失效转人工处理。

## 6. 投递与安全边界

MVP 用户自行投递，记录标记为 user_reported。没有回执不能显示网站已确认；未知结果是合法状态。JSON 导出只能证明导出了什么，不能证明最后填写和提交了什么。扩展方案见[浏览器集成](browser-integration.md)。

第一阶段限定本机单用户：密钥在服务端环境，日志脱敏，限制输入大小与模型预算；JD、网页、简历均视为数据，不执行其中指令。未来采集要防 SSRF，扩展要防页面提示注入。

迁移须有版本，并验证备份恢复。开放公网或多用户前增加认证、资源归属校验、访问审计和删除策略。MVP 不包含微服务、多 Agent 协商、自动提交、验证码绕过或批量骚扰投递。
