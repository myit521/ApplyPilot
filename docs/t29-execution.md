# T29：任务 JD 快照与单次模型边界

日期：2026-10-20。基准为 T28 清理后的 `f0b210b`，继续 PR #1，不改招聘网站行为。

## 开始前的方案审查

T27 观察到同一 JD 在页面解析后，工作流又解析一次，既重复付费，也可能产生两份要求。只删除第二次请求不足以解决排队后职位变化或批准时使用另一份 JD 的问题。因此把新任务的职位输入在入队事务中保存，贯穿生成、checkpoint 和批准版本。

模型侧先增加可独立验收的单次输入/输出边界，不新增计费平台，不把进程内累计计数误当作任务或账户配额。当前单实例恢复和有限重试保留。

## 实现与兼容

- 迁移 `006_task_job_snapshot.sql` 为任务增加可空 `job_snapshot`。新预留在同一事务锁定职位行，连同任务写入 id/source/url/company/title/raw_text/parsed；幂等重放保留第一次快照。
- worker 首次执行读取新任务快照；已有解析在本地通过当前解析门禁后复用，不发起第二次解析请求。未解析任务对入队原文解析，结果写入 checkpoint 的职位快照，再用于生成及批准。
- 批准仍校验当前事实修订并在同一事务冻结版本，但新任务的职位内容取自图中的输入快照，不用后来改过的职位行覆盖。live job 仍被锁定并校验存在，快照 job_id 不匹配时拒绝。
- 迁移不补造旧任务的原始输入。旧任务字段为 NULL，沿原有执行/批准路径兼容；它们不具备本次新任务的入队快照保证。
- ready 要求迁移 006；升级前按 T12 备份。直接 Python 部署先执行 `python -m applypilot.db` 再启动应用；Compose 应用启动命令自动迁移。不要删除卷完成升级。

输入冻结的是**入队时数据库中的职位**，不证明此前某个浏览器标签页显示的匹配报告与其相同；页面报告修订令牌尚未实现。复用解析仍是规则和结构验证，不证明真实语义完全正确。

## 默认 DeepSeek 调用边界

- 默认 system+user 合计至多 64000 字符，超限在 HTTP 前拒绝；不是 token 上限。
- 每次请求显式携带 `max_tokens=2048`。构造参数可调整正整数上限，拒绝 bool、零、负数和非整数；默认 API 使用上述值，不新增环境配置。
- 只接收成功、正常结束 `finish_reason=stop`、非空字符串内容；异常信封、非 JSON、截断/其他结束状态和超过 32768 字符的内容均以不含响应体的 ModelError 拒绝，不把部分 JSON 继续交给校验/批准。
- 保留超时/连接失败、429、5xx 的既有可重试分类；本适配器不新增网络重试。应用生成重试与 worker 尝试仍有原有上限。

这不是账户、日预算、任务总 token 或人民币费用配额，也不限制 HTTP 库读取响应体时的全部网络字节；没有新增持久化 token 账本。大量事实或修改意见超过输入上限、输出过长时可能需要人工缩减材料，本轮不自动提高上限。事实导入、职位解析、生成和语义复核共享默认适配器的单次边界。
