# T28：源码样例与公开历史隐私修复

日期：2026-10-20。沿用用户此前删除公开简历及覆盖历史的授权，未执行真实投递或外部通知。

## 问题与范围

T27 最新证据提交的托管 CI 已通过。但 T26 只核对文件路径，未覆盖源码中的个人经历样例；进一步检查发现旧冒烟入口、部分测试和早期设计文档仍有具体学校/单位及原始演示故事。不能把“无 DOCX 路径”描述为“全仓脱敏”。

本轮使用新编合成机构名替代已确认的标识，匿名化旧批次字段示例，历史冒烟脚本的简历输入整体替换为最小合成材料。保留业务测试需要的技能、指标和反例结构，不修改冻结 JSON、人工金标、模型结果或哈希门禁。

当前旧冒烟命令直接退出 2，只向 stderr 提示页面入口；不读取材料、不联网、不调用模型。它既已不符合审批修订 API，也没有请求预算及生成后逐版本确认，故选择停用，而非继续保留无界付费路径。CI 没有调用该命令，页面和 API 主流程不受影响。

## 历史处理方法

复用此前保存在本机的 git-filter-repo，不安装新工具。先保存忽略目录内的本机 Git bundle 和公开 heads/tags 快照，另建远端镜像；备份与原始过滤策略不上传，也不交给外部模型。外部 Agent 仅审查已经匿名化的当前文件。

首次镜像扫描检查 388 个可达文本 blob：学校标识命中 6 个、单位标识 41 个、批次字段 8 个、个人项目名 4 个。命中数字按每类含标识的唯一 blob 统计，类别间可能重叠；不是人数或文件数。简历 DOCX/PDF、dump、`.env` 和私有简历上下文路径数为 0。手机号样式只在 3 个测试文件中出现，经本机核对均为常见合成号码；未检出高置信 key 样式。这不是覆盖所有姓名、图像和秘密类型的保证。

过滤仅处理已确认文本标识和旧简历输入；公开分支保持原有拓扑、功能范围与分支名。推送需使用逐分支原 SHA 的 force-with-lease 与 atomic，防止覆盖审查期间新增的远端工作；不删除分支、不合并 main。main 的隐私历史会重写，但不会因此集成 T7 之后的新功能。

处理后的提交 ID 会变化。旧报告保留其当时实际运行的 source_commit、用量和内容摘要，不伪装为重新调用；本机保留提交映射用于追溯。不要从旧本地分支、旧工作树或备份直接推送，以免重新引入原历史；建议后续从清理后的公开仓库重新克隆。

## 验证与剩余限制

新回归用例拦截 HTTP 客户端和交互输入，证明旧入口不会重新触发付费生成/批准：在旧脚本的隔离副本上 1 failed，在停用入口上 1 passed。测试只使用本机替身，不调用模型。

首次全量尝试时 Docker 未运行，出现连接失败；另一次受限运行出现 Windows 控制台句柄异常，均不算应用验收通过。已启动 Docker，在正常测试环境重跑既有完整套件：**318 passed、3 warnings in 128.71s**。新增停用入口用例另外 **1 passed**；没有将这两次运行伪装成一次 319 项全量。公开分支清理后的新鲜克隆审计结果在完成后补记。

CodeBuddy 只读静态审查当前匿名化文件，未发现阻断项，未运行测试。所提注释编号、原有测试替身语义范围与方法顺序均非本轮引入，不为此扩大修改；文档入口和 CI 调用由主审另行检查。新增停用入口回归由主审负责。

GitHub 旧提交对象、PR 旧 diff、缓存、fork 或其他人的克隆可能仍有副本，重写可达 heads/tags 不等于平台已彻底擦除。GitHub 支持侧清除旧对象仍未验证。本机旧备份与其他工作树不属于公开清理完成证明。
