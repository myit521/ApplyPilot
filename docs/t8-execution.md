# T8 持久化任务与单实例恢复执行记录

验收日期：2026-10-09。基准提交 `adcb223`。T8 将创建工作流的“先起 daemon 线程、后写运行行”改为 PostgreSQL 原子占位和一个由应用生命周期管理的 worker。此记录只说明当前本机原型的能力。

## 实现与操作

- `004_workflow_tasks.sql` 保存 run、职位、全局唯一的可选幂等键、任务状态、尝试次数、下次执行时间、取消标记和脱敏错误。新库或已有数据卷须先运行 `python -m applypilot.db`；`/health/ready` 要求 004 迁移就绪。
- `POST /api/workflows` 在同一事务中创建 `workflow_runs` 和 `workflow_tasks`，提交后唤醒单 worker。同键同职位返回原 run（包括失败/取消状态）；异职位返回 409；无键每次新建。旧 `wf_<key>` run 无法证明职位归属时拒绝复用。
- `GET /api/workflows/{run_id}` 显示排队、运行、重试等待、失败和取消状态及持久化错误码；`POST /api/workflows/{run_id}/cancel` 请求取消。运行中的模型调用不会被强制中断，但返回后及下一节点前检查取消标记；已批准版本不能取消。
- worker 以 `FOR UPDATE SKIP LOCKED` 领取到期任务，单实例串行执行；启动时收回遗留 `running`，从 PostgreSQL checkpoint 继续。超时、连接失败、429 和 5xx 最多执行 3 次并退避；非临时错误和耗尽次数持久化失败。任务尝试次数与图内事实校验重试次数分开。
- PostgreSQL 批准记录始终优先。启动对账会将已批准任务收敛为完成；T7 冻结事务、哈希、审计事件与手动 checkpoint 对账方式没有改变。

## 验证

Windows Python 3.13.5；真实临时 PostgreSQL、空向量替身和合成模型适配器，未调用真实模型。执行：

```powershell
python -m pytest -p no:cacheprovider -q
```

全量结果：**194 passed，1 条 Testcontainers 导入路径弃用警告，81.86 秒**。针对性验证包括数据库迁移重复执行、两连接并发同键占位、领取互斥、取消与结果落库竞争、旧 run 冲突、重启收回 running、checkpoint 中途失败后接续、连续暂时性故障上限、落库失败注入后 worker 自恢复、批准后重启不重复冻结，以及杀停真实子进程后重启收回任务。所有测试都使用合成职位和事实。

独立只读复审由 DSH 执行；其指出的 worker 落库异常可杀死线程的问题已修复，并增加故障注入回归。DSH 曾调用一次被明确禁止的 `pwsh` 只读 Git 查询，因已知 Win32 5 沙箱错误失败；该调用没有执行测试或写入项目。CodeBuddy 实现了任务仓库切片，未自行运行测试；其 `schema_ready()` 初稿有不可达的 004 检查，已由协调方修复并补回归断言。上述复审报告不替代测试结果。

## 边界

仅支持一个应用实例和一个 worker；没有租约、跨实例仲裁或消息队列。模型调用在进程崩溃后可能重放并再次计费，不能宣称 exactly-once；业务批准仍依赖 T7 唯一约束和对账。任务恢复自动进行，已批准但 checkpoint 未同步的图状态仍通过审核页由用户手动触发对账。`/health/ready` 不检查模型密钥、worker 心跳或任务业务结果。

取消只提供 API，页面按钮和完整导航属于 T10。真实模型限流、长时间网络故障、DOCX 视觉质量、多实例行为及招聘网站填写不在此次验收范围；真实投递仍只能由用户自行完成。
